Lecture 18 · Module 4

RoboDK API — MATLAB ↔ simulator

Connect your code to the simulated robot. Send joint targets and end-effector poses; read back the actual values; close the loop between your IK solver and a moving 3D arm.

Why a simulator

Before wiring up €40k of real robot, you debug everything against a simulator. Same DH parameters, same controller behaviour, but no physical risk and no factory time slot. RoboDK is the one we use because it has a clean API and ships with most industrial robot models pre-built.

RoboDK is a lightweight industrial-robot simulator with APIs for MATLAB, Python, and C++. The Cobra, the UR5, the ABB IRB4400 — all of them — ship with the install, complete with their DH parameters and joint limits. You write code as if it were going to a real robot; you point the API at the simulator instead.

Connecting from MATLAB

Three lines of MATLAB connect to a running RoboDK instance and grab a robot handle:

rdk = Robolink();
robot = rdk.Item('UR5');
robot.setJoints([0, -90, 90, -90, -90, 0]);  % degrees

The first call opens the API; the second finds the named robot in the loaded scene; the third drives it. Joint values are degrees by default for revolute, metres for prismatic.

The useful API surface

  • setJoints(q) — drive the robot to a joint vector.
  • getJoints() — read current joint values.
  • setPose(T) — drive the end-effector to a 4×4 pose. RoboDK runs IK internally.
  • getPose() — read end-effector pose as 4×4.
  • moveL(T), moveJ(T) — built-in trajectory primitives.

That's essentially everything we need for the rest of Module 4.

Quick recap

  • RoboDK is a free industrial-robot simulator with MATLAB/Python APIs.
  • API is small: setJoints, getJoints, setPose, getPose, moveJ, moveL.
  • Develop against the simulator, deploy unchanged to the real controller.
