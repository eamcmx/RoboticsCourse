Lecture 07 · Module 2

RPP robot — and a graphical interface to drive it

A revolute base, two prismatic slides. The first robot whose joint values aren't the same as world coordinates. We also build the slider GUI pattern that every later lecture reuses.

Anatomy

A revolute joint at the base, then a vertical slide, then a horizontal extension. This is the kinematic skeleton of every cylindrical-coordinate robot ever built — most factory pick-and-place arms reduce to this shape with a wrist on top.

The RPP arm has three joints: q1 rotates the column (revolute), q2 moves vertically (prismatic), q3 extends radially (prismatic). Unlike the PPP, the joint variables and world coordinates are no longer the same — the arm reaches a cylindrical workspace, not a Cartesian one.

Play with it

Drag q1 to swing the column, q2 for the vertical slide, q3 for the horizontal extension. Watch the end-effector position update.

Why the workspace is a cylinder

Hold q2 and q3 constant and sweep q1 through ±π. The end-effector traces a circle. Vary q2 — the circle moves up and down. Vary q3 — the radius grows. The set of reachable points is a cylindrical shell, not a box.

Position in cylindrical coordinates: radius = q3, angle = q1, height = base + q2. The conversion to Cartesian is exactly the polar formula.

Building the slider GUI

Once you have a forward-kinematics function, the easiest way to debug it is to wrap it in a GUI with one slider per joint. In MATLAB the pattern is just `uislider`. In a browser it's an HTML range input. The widget you're looking at is exactly that — a thin layer around a slider element that calls back into the FK function on every change.

The robot-viewer widget on this page is roughly 250 lines of JavaScript wrapping the same FK function we built in Lecture 06. The MATLAB equivalent is even shorter — the language has slider widgets built in. The key insight: the GUI is the cheap part; the FK is the load-bearing part.

Quick recap

  • RPP joints: revolute base, vertical slide, horizontal extension. Cylindrical workspace.
  • Joint variables ≠ world coordinates here. The conversion is the polar formula.
  • The slider GUI pattern is just one input range per joint, calling FK on each change. Reused unchanged in every later robot.
Homework 07 · due before next session

Cylindrical workspace, by hand and by code

  1. By hand: derive the world-frame position of the RPP end-effector from the DH parameters. Confirm it equals (q₃·sin q₁, −q₃·cos q₁, 0.2 + q₂) under our convention.
  2. In code: implement fk_RPP(q) in MATLAB. Test against three poses you can verify by inspection.
  3. Plot the RPP's reachable workspace. Sample 30 values of q₁ ∈ [−π, π], 10 values of q₂ and q₃ across their ranges; scatter the end-effector positions. The result should look like a cylindrical shell.
