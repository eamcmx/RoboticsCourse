Lecture 14 · Module 4

move J — interpolate in joint space

The simplest trajectory primitive every controller ships with. Linearly interpolate joint values from start to goal — no constraint on what the end-effector path looks like in task space.

The simplest possible motion

When you want the robot to go from configuration A to configuration B and you don't care what shape the end-effector traces, the right primitive is move J. Just linearly interpolate every joint value over time. The arm gets there fast, the math is trivial, and the end-effector path is whatever it happens to be.

The simplest motion you can ask of a robot: from joint vector qstart to joint vector qgoal, linearly interpolate every joint independently over time. The end-effector traces some curve in 3D — usually a curved arc, not a straight line — but you don't control or care about its shape.

When move J is wrong

You should not use move J when the end-effector path matters. Welding a straight seam, drawing a line, applying glue along an edge — for any of these you need move L. The robot doesn't care that move J's path looks like a curve; the work piece does.

move J's end-effector path is determined by FK applied along the linear-in-q curve. That path is generally not a straight line in 3D. For tasks that require the end-effector to follow a specific shape — laser-cutting, welding, gluing along an edge — move J is the wrong tool. Lecture 15 builds the right one.

Quick recap

  • move J interpolates joint values linearly from qstart to qgoal.
  • End-effector path is whatever falls out — usually curved.
  • Use it when the path doesn't matter; use move L when it does.
