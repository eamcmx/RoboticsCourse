Lecture 06 · Module 2

PPP robot — three prismatic joints

The simplest possible kinematic chain. Three slides, three joint variables, end-effector position equal to the sum of three orthogonal translations. We walk every concept of forward kinematics on this robot before moving to harder ones.

Anatomy of a Cartesian gantry

This is the simplest robot we can build. Three perpendicular slides — one along x, one along y, one along z. The end-effector position is just the sum of three numbers: how far each slide has extended. We solve forward kinematics in our heads. The point of doing it on this robot is to see all the machinery that makes it formal.

A PPP robot — three prismatic (P) joints in series, each orthogonal to the previous — is the kinematic equivalent of a 3D printer head: the end-effector goes wherever the three slides have been positioned. By inspection,

We could stop there. But the goal isn't just to know where the end-effector is on this robot — it's to write the same machinery (DH parameters → per-joint T → composed FK) we'll re-use on the next six robots without any change. So we'll go through the formal procedure even when we don't strictly need it. The reward shows up in Lecture 09, when the robot has six revolute joints and you can no longer do the FK in your head.

Play with it first

Drag the three sliders. The cylindrical rod showing each link extends as you slide. The mobile (orange) frame at the tip of the chain is the end-effector pose; its position should equal (q1, q2, q3) within rounding.

Sanity check

With all three sliders at home (0.30, 0.30, 0.30), the end-effector should sit at world coordinates (0.300, 0.300, 0.300). It does — read the position line in the controls. Move any slider; the corresponding world coordinate should change by exactly the slider's delta. That's what "Cartesian" means: the joint variables and the world coordinates of the end-effector are equal up to a constant.

The DH parameters

We assign one frame per joint following the standard-DH convention (full details in Lecture 10 — for now, just see the table). For each joint i, four parameters describe how frame i sits relative to frame i−1: ai, αi, di, θi. For a prismatic joint the joint variable is d; for a revolute joint it would be θ.

Compute forward kinematics in code

ROBOTS.PPP is the loaded robot definition; forwardKinematics(q, robot) returns the end-effector pose as a 4×4 row-major flat array. Compare what the function returns to the value you read off the slider widget above.

The end-effector matrix should have a translation column equal to (q1, q2, q3) up to floating-point error. The rotation block, however, is not the identity — the chain of α twists rotates the tool frame relative to the base. That's a feature, not a bug: when we attach a tool we'll get to choose its orientation through the DH design.

Quick recap

  • The PPP is three orthogonal slides. End-effector position equals (q₁, q₂, q₃) up to a constant offset.
  • Even though the geometry is trivial, we use it to walk through the whole DH → per-joint T → composed T pipeline that we'll reuse on every later robot.
  • Each joint contributes one elementary 4×4 transform parameterised by a, α, d, θ. For a prismatic joint, d is the variable.
  • Forward kinematics is the matrix product T_n = T_1 · T_2 · … · T_n.

Verify FK by hand and in code

  1. By hand: write out T1, T2, T3 for the PPP using the DH parameters above with q = (0.4, 0.5, 0.2). Multiply them in order. Show that the translation column of the product is (0.4, 0.5, 0.2).
  2. In code: implement a fk_PPP(q) function in MATLAB that takes a 3-vector of joint values and returns the 4×4 end-effector pose. Test it on q = (0.1, 0.2, 0.3), (0.5, 0, 0), and (0, 0, 0).
  3. Bonus: animate the end-effector tracing a square in the x–y plane at z = 0.4. Use a for loop over four edge segments, ten via-points each.
