Lecture 03 · Module 1

Translations and homogeneous transforms

Rotations alone don't tell us where a frame is, only how it's oriented. We need translation too. The 4×4 homogeneous transform is the trick that lets us pack both into a single matrix that composes by ordinary multiplication.

The problem with rotation alone

Rotations describe orientation only. They tell you which direction the gripper is facing, but not where in the workspace it sits. To capture position we need translation, and to chain transformations cleanly we want both packed into a single matrix.

A 3×3 rotation matrix R describes how the axes of the mobile frame are oriented relative to the fixed frame. But it says nothing about where the mobile frame's origin sits — every rotation matrix is anchored to the same origin.

For a real robot, that's not enough. The end-effector of the SCARA on your bench has both a position (a place in the workspace) and an orientation (a direction the gripper is facing). We need both, in one mathematical object that composes cleanly when we chain joints together.

Pure translation, no rotation

Start with the simplest case: no rotation, just translation. The mobile frame is parallel to the fixed frame but its origin is offset by a vector p = (pₓ, p_y, p_z). Drag the three sliders below to translate frame B around. The 4×4 matrix on the right updates live — notice the rotation block stays fixed at the identity, and only the right column changes.

T_y(d) and T_z(d) follow the same pattern — identity rotation block, single non-zero translation entry. And if you want to translate along all three axes at once, you just put pₓ, p_y, p_z in the right column.

The general homogeneous transform

Pack the rotation into the top-left 3×3 block, the translation into the right column, and a fixed bottom row [0 0 0 1]. The result is the homogeneous transformation matrix — a 4×4 that holds both kinds of information and composes by ordinary matrix multiplication.

In general, a homogeneous transform T packs a rotation R and a translation p into one 4×4. The widget below has all six sliders — three for rotation around the fixed axes (same convention as Lecture 02: each slider rotates around its world axis) and three for translation. As you drag them, watch how the 4×4 matrix updates — the rotation slider changes affect only the top-left 3×3 block, and the translation sliders affect only the right column.

Why the bottom row?

The [0 0 0 1] looks like padding, but it's the whole point. To use the matrix on a 3-vector, we extend the vector to 4 entries by appending a 1: a point becomes (x, y, z, 1)ᵀ. The bottom row preserves that 1 under multiplication, which is what makes translations work as matrix multiplications instead of additions. Vectors that represent directions rather than points get a 0 at the bottom, which is what makes them immune to translation.

Order matters: rotate-then-translate vs translate-then-rotate

Like with rotations, composition order matters. Rotate first, then translate moves the frame's origin in the world direction by p. Translate first, then rotate moves the origin in what is initially the world direction, but the rotation then sweeps that origin around the world axis — landing somewhere else entirely. Reading composite transforms

T_AC = T_AB · T_BC reads as: "to express something from frame C in frame A, go from C to B (rightmost), then from B to A (leftmost)." Right-to-left composition again, same rule as for rotations. Once you internalise this you can chain any number of frames — that's exactly how we'll handle a multi-joint robot in the next module.

Quick recap

  • Rotation describes orientation; translation describes position. Real frames need both.
  • The 4×4 homogeneous transform packs R into the top-left, p into the right column, [0 0 0 1] into the bottom row.
  • The bottom row is what makes translation behave as matrix multiplication.
  • Homogeneous transforms compose by ordinary right-to-left matrix multiplication.
  • To transform a point, append a 1 to make it a 4-vector and multiply by T.

Build, compose, transform

  1. By hand: write the homogeneous transform that translates by (1, 2, 3) and then rotates by 30° around z. Show your work as a single matrix product, then multiply it out.
  2. In the sandbox: build the same transform two ways — first as a single homog(rotZ(30), [1;2;3]), then as transl(1,2,3) * homog(rotZ(30), [0;0;0]). Are they equal? If not, why not? Try the other order: homog(rotZ(30), [0;0;0]) * transl(1,2,3) — and explain what changed.
  3. Take the point (1, 0, 0) in the rotated/translated frame and find its coordinates in the original frame. Verify your answer by sketching the frames on paper and reading the coordinates off the picture.
