Lecture 20 · Module 4 — Final assignment

Master–slave — the final assignment

Robot A holds a plate with a trajectory drawn on its surface. You steer A with the joystick. Robot B compensates in real time so its end-effector keeps tracing the same line on the plate as A is manipulated. Everything from the term, in one system.

The task

This integrates everything we've built. You've got a teach-pendant from Lecture 17 driving robot A. Robot A is holding a plate. The trajectory you want robot B to draw is fixed in the plate's frame — but the plate moves whenever you move A. So robot B has to use the chain from Lecture 19 to re-target itself, and the IK from Lecture 12 to actually move there. If you can solve this in two weeks I'll be impressed.

You've seen every piece needed for this. Here it goes together:

  • An Arduino with two joysticks (Lecture 17) drives robot A in real time.
  • Robot A holds a plate rigidly at its end-effector. The plate has a target trajectory defined on its surface — say, a square or your initials.
  • Robot B has to draw that trajectory on the plate, no matter how A moves the plate around.
  • The chain TA·TplateA·Tviaplate from Lecture 19 turns plate-frame targets into world-frame targets for B.
  • B's IK from Lecture 12 turns those world-frame targets into joint values for B.
  • Both robots' poses are visualised in RoboDK using the API from Lecture 18.

System architecture

Three concurrent loops:

  1. Joystick → A loop (50 Hz). Reads Arduino, integrates rates into joint targets for A, sends to RoboDK.
  2. A → plate-pose loop (50 Hz). Reads A's actual joint values from RoboDK, computes TA, then Tplate0 = TA·TplateA.
  3. Plate → B loop (50 Hz). For the current via-point in the trajectory, computes Tvia0 = Tplate0·Tviaplate, runs IK warm-started from B's last solution, sends qB to RoboDK.

In MATLAB the easiest implementation is a single 50-Hz timer that runs all three sequentially. Async is overkill for this loop rate.

Suggested milestones

  1. Day 1: Get the joystick driving robot A in RoboDK. Lecture 17 + 18 wired up.
  2. Day 2: Define a static plate trajectory (a square). Robot B traces it while A is held still. Lecture 15.
  3. Day 3: Wire up the plate-pose chain. Move A by hand; observe that B's targets in world frame move with the plate. Lecture 19.
  4. Day 4: Connect joystick → A → plate → B end-to-end. Move the joystick slowly and watch B compensate.
  5. Day 5: Tune for stability — add damping, handle unreachable regions, smooth the rate command.

Specific hints

  • Run RoboDK at the highest update rate it allows. The visual trace is your debugger.
  • Cache TplateA once at startup — it's a constant.
  • Plot B's IK iteration count over time. Spikes indicate near-singularity; that's where to add damping.
  • If B can't reach a target, freeze instead of jumping. The ugliest failure mode is a violent re-orientation when B's solver flips branches.
  • Add a "kill switch" early. Mode toggle on the joystick goes to "hold" — both robots stop moving.

What success looks like

You move the joystick slowly. Robot A rotates the plate in place. Robot B's end-effector continues to trace the same square on the plate's surface — visually it's as if B and the plate are rigidly coupled, even though they're two independent six-DOF arms.

If you tilt the plate aggressively, B will eventually fail to reach. That's expected. A graceful failure (B freezes, no joint flip, controller stays stable) is part of what we're grading.

Homework 20 · due before next session

The final assignment

  1. Implement the system end-to-end as described above. Use RoboDK for the simulator, MATLAB or Python for the host loops, an Arduino for the joystick.
  2. Document the architecture in a one-page diagram: data flow, update rates, code organisation.
  3. Submit code in a GitHub repo plus a 5-minute screen-recorded demo.
Deliverable 1
Architecture diagram
Single page showing the three loops, the data passed between them, and the update rates. Include the chain TA·TplateA·Tviaplate labelled.
Deliverable 2
Code
Full source on GitHub. Must run end-to-end with RoboDK and (optionally) the Arduino. If hardware unavailable, simulate the joystick with two sliders.
Deliverable 3
5-minute demo
Recording showing the joystick moving, robot A re-orienting the plate, robot B tracking. Demonstrate at least one graceful failure when a target becomes unreachable.
